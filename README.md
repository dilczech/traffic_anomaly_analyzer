# Анализатор дорожного трафика

Почасовой анализ Excel-выгрузок АПУД: поиск отклонений суточного объёма,
формы профиля, технических сбоев и межгодовых отклонений одинаковых месяцев.
Результаты — Excel-реестр и графики аномальных дней.

## Установка и запуск

Python 3.11 или новее. Из корня проекта:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e .
.venv\Scripts\python -m traffic_analyzer --input input_data --output reports
```

Прежний запуск также работает:

```powershell
python traffic_anomaly_analyzer.py --input input_data --output reports
```

После установки доступна команда `traffic-analyzer`. Флаг `--no-plots`
отключает построение графиков. Коды завершения: `0` — обработано успешно,
`1` — ошибка, `2` — отчёт построен, но часть входных файлов пропущена.
Ошибки отдельных источников выводятся в журнал и возвращаются в результате.

По умолчанию графики создаются только для дней с аномалиями трафика.
Проблемы качества этих же дней показываются отдельными диагностическими
графиками. `--include-quality-plots` добавляет дни только с проблемами
качества; `--monthly-plots` включает месячные обзоры. Полный Excel-реестр
не зависит от этих фильтров.

## Структура

```text
traffic_anomaly_analyzer.py  # Совместимый прежний вход
traffic_analyzer/
    __main__.py             # python -m traffic_analyzer
    cli.py                  # Аргументы, сообщения и код завершения
    service.py              # Общий сценарий обработки run_analysis
    models.py               # Настройки и структурированный результат
    events.py               # Единое описание события и его интервала
    sources.py              # Интерфейс источника и локальные файлы
    validation.py           # Проверка контейнера и шапки Excel
    parser.py               # Excel → DataFrame
    quality.py              # Часовая сетка, пропуски, пригодность данных
    balance.py              # Общие допуски и месячная диагностика учёта
    priorities.py           # Приоритет ручной проверки и его обоснование
    baseline.py             # Общая опорная норма для анализа и графиков
    detectors.py            # DataFrame → суточные и месячные срабатывания
    reporting.py            # Excel-реестр
    report_views.py         # Состав столбцов и единицы каждого листа
    legend.py               # Пояснения к отчёту и обозначениям
    palette.py              # Общие оттенки Excel и графиков
    plots.py                # Графики, Matplotlib загружается при построении
    diagnostic_plots.py     # Отдельные представления типов суточных событий
    monthly_plots.py        # Дополнительные месячные обзоры
    systematic_plots.py     # Диагностика месяцев с систематическим расхождением
tests/
    test_pipeline.py        # Проверки границ и сценария обработки
    test_analysis.py        # Контролируемые пропуски и изменения трафика
input_data/                 # Исходные файлы
reports/                    # Результаты
pyproject.toml              # Зависимости и установка пакета
```

Направление обработки:

```text
CLI / будущий API → service → sources → validation + parser
                                      → quality → baseline → detectors
                                                    ↓            ↓
                                                reporting + plots
```

Детекторы не читают файлы и не знают о CLI, HTTP или Docker.
`service.py` связывает этапы. Единый файл запуска остаётся маленьким.

## Входные файлы

Поддерживается `.xlsx` с почасовой выгрузкой текущего формата: 29 столбцов,
дата в A, общая интенсивность в B:D, семь категорий ТС в E:Y,
скорость по направлениям в Z:AA, загрузка в AB:AC.
Многоуровневая шапка должна находиться в первых 20 строках активного листа.
Проверяются названия основных групп и их позиции. Внутри листа участки
расположены последовательно и обозначены строками с километражем.

Парсер проверяет контейнер Excel, шапку и наличие распознаваемых записей.
Это базовая проверка поддерживаемого формата, а не полный аудит качества данных.
Значения дат читаются из Excel datetime или строк вида `01.01.2020 00:59:59`.
Итоговые строки пропускаются. `.xls` нужно предварительно сохранить как `.xlsx`.
Временные файлы Excel `~$...` не обрабатываются. Повторения «участок + время»
останавливают обработку до записи отчёта, чтобы не удваивать интенсивность.

## Использование из Python и будущего API

```python
from pathlib import Path
from traffic_analyzer import AnalysisConfig, LocalFileSource, run_analysis

result = run_analysis(
    [LocalFileSource(Path("input_data/report.xlsx"))],
    AnalysisConfig(output_dir=Path("reports/job_001"), generate_plots=False),
)
print(result.record_count, result.anomalous_day_count, result.report_path)
```

Результат содержит количество записей, участков, срабатываний, уникальных дней
и месяцев по участкам, пути результатов и ошибки пропущенных источников.
Сервис синхронный. Для будущего веб-приложения длительный анализ следует
запускать отдельной задачей, а результат привязывать к идентификатору задания.
Каждому заданию нужна своя выходная папка: одинаковые пути перезаписываются.
Для повторного запуска используйте новую папку, чтобы не смешивать старые графики.

Pydantic пока не подключён. В API он сможет проверять параметры запроса,
настройки и ответы. Сам Excel проверяет `validation.py`: Pydantic не заменяет
чтение книги и проверку её содержимого. Загруженный через API файл можно
сохранить во временную папку и передать через `LocalFileSource`.
До публикации загрузки также потребуются ограничения размера файла и
распакованного содержимого, времени обработки и ресурсов задания.

## Файлы с сайта

`FileSource` задаёт два элемента: `name` и контекстный менеджер
`materialize()`, предоставляющий локальный `Path` на время чтения.
Будущий адаптер сайта скачает отчёт во временную папку, отдаст путь и удалит
файл при выходе из контекста. Дальнейшие проверки и анализ останутся общими.

Скачивание пока не реализовано: нужен адрес сайта, способ авторизации и
понимание, отдаёт ли он прямой Excel или формирует выгрузку по запросу.
При реализации в адаптере задаются таймауты, ограничения размера,
разрешённые адреса и правила повторных попыток. Если сайт отдаёт HTML/JSON,
для такого источника понадобится отдельный парсер.

## Docker и фронтенд

Контейнер и HTTP-сервер пока не добавлены. Пакет устанавливается из

## Как работает анализ

1. Для каждого участка восстанавливается часовая сетка от начала первого
   до конца последнего дня общего входного периода. Вне этого периода
   наличие измерений неизвестно. Дубликаты проверяются после округления к часу.
2. Отдельно отмечаются отсутствующие/нечисловые/невозможные измерения,
   несогласованные суммы транспорта и подозрения на залипание датчика.
   Серии от 12 часов с одновременными нулями потока, скоростей и загрузки
   отдельно отмечаются как подозрение на нулевую телеметрию. Их исходные
   нули сохраняются, но они не участвуют в норме. Это не доказанный отказ.
   Пропуск не превращается в ноль. Для нормы пригодны только полные сутки
   с корректными количествами и согласованными суммами без залипания.
3. Норма — медиана других пригодных дней того же дня недели в окне ±84 дня.
   Требуется минимум 6 опорных дней. Список праздников задаётся через
   `AnalysisConfig.holiday_dates`; автоматического календаря пока нет.
   Графики используют именно ту норму, по которой работали детекторы.
4. Робастный масштаб: max(1,4826 × MAD; 10% медианы; нижний предел).
   Нижние пределы — 20 авт./ч, 100 авт./сут, 3 км/ч, 2 п.п. загрузки.
   Диапазон на графике — медиана ± 3,5 масштаба с физическими границами.
   Это диапазон детектора, не доверительный интервал и не вероятность.
5. Часовое отклонение: |Z| ≥ 3,5 и разность ≥ max(35% нормы; 50 авт./ч).
   Суточное: |Z| ≥ 3,5 и разность ≥ max(25% нормы; 100 авт./сут).
   Корреляция полного профиля < 0,70 при объёме > 1000 отмечается отдельно.
   Часовые тесты применяются к общему потоку и обоим направлениям.
6. Скорость < 35 км/ч и загрузка > 60% проверяются одновременно в одной
   записи для каждого направления при потоке > 0. Отдельный статистический
   тест скорости требует падения от нормы на 15 км/ч и Z ≤ −3,5.
7. Устойчивое изменение — минимум 7 полных дней подряд с отклонением
   в одну сторону более 25% от однотипных дней предыдущих 168 дней.
   Для каждого дня окна требуется 6 опорных дней. История фиксируется
   до начала окна. Границы окна не означают точные границы режима.
8. Полнота и пригодность месяцев проверяются при любом количестве лет.
   ССИ считается только по полным пригодным суткам. Взвешенная скорость
   использует часовые скорости и соответствующие количества автомобилей.
   YoY сравнивает только месяцы с пригодностью ≥95% с тем же месяцем
   других пригодных лет, исключая текущий год. Пороги: ССИ ±25%,
   доля больших грузовых и автопоездов ±8 п.п., скорость −15 км/ч.

### Сведение количества автомобилей

Для каждого часа проверяются общий поток против суммы направлений и поток
каждого направления против суммы семи категорий. Допуск:
`T = max(10 автомобилей; 2% × max(объявлено; пересчитано))`.
Расхождение ровно на границе допуска принимается. В пределах допуска час
не исключается из нормы из-за баланса; другие дефекты проверяются отдельно.
Пропущенное слагаемое не считается нулём.

Мелкие расхождения не создают часовых событий и графиков. На листе
«Учёт по месяцам» по каждому равенству показаны проверенные часы,
малые и значительные расхождения, дни, максимальная/медианная разность и знак.
Это диагностические показатели учёта; они не означают число потерянных авто.

Систематичность: минимум 30 часов с ненулевой разностью, 7 разных дней
и 80% случаев одного знака в отдельной проверке месяца. Учитываются и
малые расхождения в допуске. Прошедшие проверки одного участка/месяца
объединяются в одно событие; связанные проверки одного часа не суммируются.
В `plots/systematic` сохраняются только графики обнаруженных систематических
аномалий: разность по времени и границы допуска. Они включаются в индекс
как `period_charts`; суточные графики остаются в `charts`.
Все пороги доступны в `AnalysisConfig`.

### Приоритет ручной проверки

«Наблюдение» заменено на **«Проверить»**, «Высокий» — на
**«Проверить в первую очередь»**. Для часовых сигналов первая очередь
назначается при длительности от 2 ч, Z от 6 либо отклонении от 50%.
Совпадение по времени и направлению сигналов скорости и объёма повышает
приоритет; общий и направленный объём сами по себе не считаются независимыми
подтверждениями. Объём суток и скорость при загрузке идут в первую очередь;
форма — при r < 0,40, доли направлений — при разнице от 40 п.п.
Допустимость опорной выборки проверяется до детекции.
Причина приоритета добавляется в пояснение. Приоритет не устанавливает
причину события и не является вероятностью аварии/поломки.

Параметры окна, минимальной выборки, порогов интенсивности, скорости/загрузки,
пригодности месяца и длительности режима доступны через `AnalysisConfig`.
Межгодовое сравнение при одном опорном годе — сравнение двух периодов,
а не оценка устойчивой многолетней нормы.

## Отчёт и графики

Excel содержит сводку, события качества данных, аномалии трафика,
устойчивые изменения, показатели и события месяцев, годовые показатели,
покрытие суток и статус нормы. Если источники пропущены, добавляется лист
с их ошибками. Последний лист — **«Легенда»**: обозначения, единицы, условия
срабатывания, параметры активной конфигурации и ограничения интерпретации.

Состав столбцов зависит от назначения листа. На листе качества данных нет
Z, нормы и опорных выборок: вместо общего «Факта» показаны затронутые часы.
Месячные проверки качества показывают пригодность, требование и нехватку
в п.п.; опорные годы добавляются только при межгодовых событиях.
В месячных показателях убраны дублирующие год/месяц и булевы TRUE/FALSE:
выведены статусы качества и доступности сравнения. На листе покрытия
показаны причина недоступного суточного объёма и статус нормы.

Числовые пропуски в отчёте заменены на «—». Это представление при экспорте,
исходные DataFrame не изменяются. Реальный ноль остаётся числом 0.
Отклонения трафика имеют отдельную единицу: интенсивность — %, скорость —
км/ч, доли — п.п.; для корреляции отклонение не вычисляется. Z статистической
проверки скорости — максимум абсолютного часового Z данного интервала.

Общая палитра находится в `palette.py`: сине-серые заголовки, графитовый
текст и лёгкое чередование строк. Выделяется только ячейка приоритета:
светло-красный фон для «Проверить в первую очередь», светло-янтарный для «Проверить».
Графики используют те же спокойные синий, серо-синий, красный и фиолетовый.

Каждый тип события получает своё представление:

| Событие | Что показывает график |
| --- | --- |
| Часовой спад / всплеск | Факт, опорный профиль, диапазон и конкретные часы по затронутым направлениям |
| Суточный объём | Профиль-контекст и отдельные столбцы факта и нормы суток |
| Форма профиля | Исходные и нормированные по объёму кривые, коэффициент корреляции |
| Низкая скорость | Профиль скорости и разность с опорной скоростью |
| Скорость при загрузке | Синхронные панели скорости, загрузки и ненулевого потока |
| Направления | Часовые доли и дневная доля относительно нормы |
| Не сходятся суммы | Таблица конкретных чисел: объявлено, сумма, разность и допуск; только превышения допуска, без совпадающих кривых |
| Пропуски | Матрица присутствия и пригодности измерений по часам |
| Залипание | Постоянный участок и разность соседних часов |
| Нулевая телеметрия | Значения всех семи каналов с выделенной нулевой серией |
| Некорректные поля | Исходные числовые значения и проблемные часы конкретных полей |

Пороги на графике совпадают с детектором. Поля до маскирования сохранены
в `PreparedData.raw_values` для диагностики некорректных чисел; статистика
по-прежнему использует только проверенные значения. Нечисловые поля остаются
неизвестными, не подменяются нулями.

В `plots/дата_хеш-участка/` находится один PNG на тип события. Несколько
интервалов одного типа объединены на нём. Актуальные графики и интервалы
перечислены в `plots/index.json`. При повторном запуске старые файлы не
удаляются: ориентируйтесь на индекс или используйте новую выходную папку.
Заголовки графиков явно синие; в шапках Excel текст светло-голубой.

При `--monthly-plots` в `plots/months` сохраняются обзоры ССИ, скоростей
и полноты/пригодности измерений. Отсутствующие значения остаются разрывами.
Недостаток лет для YoY подписан явно.

## Ограничения и проверка качества

Нормы ретроспективные: используют дни до и после проверяемого дня.
Для онлайн-мониторинга потребуется отдельная конфигурация без будущих данных.
Праздники учитываются только при передаче списка дат. Подозрение на сбой
не доказывает поломку, низкая скорость не устанавливает причину события.

Годовые показатели относятся только к доступным полным суткам;
неполный год явно подписан. Годовая сезонная модель не обучается.
Контролируемые тесты подтверждают обнаружение искусственных пропусков,
всплесков и устойчивых изменений, но не заменяют оценку точности на
размеченных реальных событиях. Пороги требуют дальнейшей калибровки.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют корректный формат, неподходящие и пустые книги, повреждённые
файлы, `.xls`, перекрытие выгрузок, частичный результат и освобождение источника.
